# Study Buddy: Architecture and Working Agreement

Read this first when continuing the project. Then read `STYLE_GUIDE.md` for the look, and `BUILD_APPROACH.md` for how Explorer's Atlas (the first module) was built.

## 1. Owner's rules (standing)
- Build only modules the owner asks for. Empty subjects stay empty.
- Parent-led tool. Everyone sees every module. Subject filters, no assigning.
- No emoji. The presentation never changes by age: the same look for every student. Friendly comes from the design system, not from cartoons.
- Difficulty is Easy / Medium / Hard / Insane, never grade levels.
- Hide unused features rather than deleting them.
- Explorer's Atlas: don't change Study map, Drag names, Find it, or Listen and tap unless asked. Flashcards show the whole continent, and their sound plays only from the speaker button. The Atlas never reads quiz questions aloud. Its map activities can be used from the keyboard (every country takes Tab and Enter), and Say names follows each student's Read aloud setting (off by default).
- Other modules read questions aloud only when the student's Read aloud setting is on (off by default). Speaker buttons always work.
- Test at 1440×900 with no scroll bars on tool screens, and with no sideways scroll at phone width (360px, Galaxy S23).
- Deliver code as downloadable files.

## 2. Vocabulary
Study Buddy → **Subjects** → **Modules** → **Tools**.
- A module has one home `subject` and a list of `tags`. A module whose tags include another subject's id shows in that subject's **Suggested** area.
- Each tool has a `difficulty`. A module's difficulty is the range of its tools, computed automatically (`SB.difficultyRange`).

Mastery is computed when the data is read, from registry rules: `masterAt` (best ≥ n) or `masterPct` (best / max ≥ share, default 0.8). A tool with `full: true` is judged on its Full result (`fullBest`/`fullMax`) instead. Changing a rule later re-grades old scores automatically.

The daily goal (20 right answers) and the streak are per student and shared across all of Study Buddy. Module-specific rewards (the Atlas passport) stay inside the module.

## 5. Module contract
**The easy way (use this for every new module):** copy `modules/english/parts-of-speech/` as the pattern.
- `index.html` loads `shared/sb.css`, the module's own CSS, `sb-core.js`, `registry.js`, `sb-module.js`, then the module's `data.js` and script.
- The script calls `SBM.start({ module: '<registry id>', defaults: {...}, tools: { <toolId>: { init(ctx), leave?(), enter?() } } })`.
- **Flashcards are practice only.** They give no credit, streak, or mastery, and record no result (registry `kind:'study'`, blurb ends "Practice only."). Credit comes only from checked tools: quizzes, sort, order, type-the-answer, explain, and the Atlas games.
- Each tool fills `ctx.panel`, and calls `ctx.credit()` / `ctx.slip()` per answer and `ctx.result(score, max)` per finished round. It uses `ctx.say(text)` for questions (spoken only when Read aloud is on), `ctx.sayButton(text)` for speaker buttons, `ctx.state` + `ctx.save()` for saved data, and `ctx.sfx` for tones.
- Tool tabs come from the registry entry, in registry order. Tabs, the header, settings, Reset, and the phone layout are handled by the shell.
- Phone layout is built in: tabs become one swipeable row, and the header and settings get compact. Keep module CSS phone-friendly with a `@media (max-width:760px)` block.

**What any module page must do (the shell does all of this for you):**
1. Load `shared/sb-core.js` with a relative path (e.g. `../../../shared/sb-core.js`), and link `shared/sb.css` (unless it brings identical CSS, like the Atlas).
2. Call `SB.requireProfile()` on load. It returns the student, or sends the page back to the hub.
3. Save its own state under `SB.moduleKey(...)`.
4. Use the standard header: an eyebrow linking back (`‹ Study Buddy · Subject`), the module title, a student chip (`SB.avatar(kid)`), and streak and today pills.
5. Use one tab per tool, with tab ids matching the registry tool ids. Open the tab given in `?tool=<id>`.
6. Call `SB.opened(module, tool)` when a tool opens, `SB.credit()` / `SB.slip()` on each answer, and `SB.result(module, tool, score, max)` when a round finishes.
7. Use `SB.sfx` for tones and `SB.say(text)` for read-aloud (it respects the student's Read aloud setting, which is off by default). Speaker buttons use `SB.sayButton(text)` and always play.
8. Put destructive actions behind `SB.requirePin(message, onOk, onCancel, { confirm: { title, text, ok } })`. The `confirm` option makes the action always ask "Are you sure?" first, even with no PIN or when the admin area is unlocked. Escape and outside taps cancel.
9. Keep working when `window.SB` is missing, if it's practical (the Atlas does).

Then add an entry in `registry.js`, rebuild, and run the tests.

## 6. Notes and caveats
- The admin PIN is a hash stored locally. It is a kid lock, not security. "Forgot PIN?" (type REMOVE, then choose a new PIN) keeps the old PIN until the new one is saved, then stamps `pinRemovedAt`; the admin area shows a dismissible note on the Progress and PIN tabs. Backup files contain the PIN hash, so keep them private.
- Progress is per browser, per device, per web address. Backup export/import moves it. `SB.checkBackup(text)` validates a file before anything is written (app name, only `studybuddy.v1.` keys, profile ids and colors, typed student records), and `importAll` restores the old data if storage runs out. Another tab changing the active student reloads this one.
- Dialogs are named by their heading (`aria-labelledby`) and keep Tab inside. `.msg` feedback lines announce themselves (`aria-live`). Text colors use the `-ink` tokens and button fills the `-fill` tokens so contrast holds in light and dark mode (see STYLE_GUIDE).
- Opened on its own, the Atlas logs one harmless "file not found" for `sb-core.js`, then runs standalone.
- The style guide says selected tabs are teal, but the real app uses navy. Study Buddy follows the app (navy).
- Atlas phone layout (v3.2): every phone rule lives in one `@media (max-width:760px)` block at the end of the Atlas CSS. On phones the Study map list is one column, the prompt sits above the map in Find it and Listen and tap, and the names and feedback sit above the map in Drag names. Desktop is pixel-identical to v3 (checked with screenshot diffs at 1440×900 and 1000×800).

## 6a. Display options and swipe
- Per-child settings `theme` (light, dark, auto = match device), `font` (standard, dyslexic), and `size` (normal, large). `SB.applyDisplay()` sets `sb-dark`, `sb-dyslexic`, and `sb-large` on `<html>` as soon as sb-core.js loads. The Display button is gone: all display options now live on the Settings page (`#/settings`), reached from the header and footer of every page.
- Dark mode works through tokens in sb.css (`--surface`, `--navy-ink`, `--track`, `--tint-*`). New CSS must use tokens, never literal white, so it follows the theme. South America has its own `html.sb-dark` block (light mode is untouched).
- OpenDyslexic: sb-core injects the @font-face rules (with absolute URLs) and sets `--font`, so every page, including South America, switches font.
- Flashcard swipe: `SB.swipeCard(stage, card, { onRight, onLeft })`. Right = I knew it, left = Still learning, a tap flips, and the arrow keys work too. Used by `SBT.flashcards` and South America.

## 6c. Shell, Settings, voice, and stopping sound
- Every page loads `shared/sb-shell.js` and calls `SB.shell(...)`. Modules built with `SBM.start` get it automatically. The hub builds its trail per route (`hub.js route()`); `window.SB_SHELL_RELOAD` re-renders the shell after the student changes.
- Settings page: Theme, Font, Text size, Sound effects, Read aloud, Voice (with Preview), and a link to the admin area. Settings are per student and need no PIN; the admin area keeps its PIN. The voice list shows only this device's English voices. `voice` is a voice id from `SB.voiceId(v)` (the voiceURI, name and language, with a number added when a device lists several voices that are exactly alike), and `''` means Automatic. Android Chrome lists many voices with the same name, so `SB.voiceLabels` adds the voice code or a number to the names, and the Voice row says which voice code is speaking. `SB.voicesFor(lang)` ranks voices with `voiceScore` (Natural/Neural/Online/Google and common female voices up, David, Mark, compact, and espeak down); `SB.pickVoice` uses the saved voice if it applies to the language, otherwise the best one. Voices differ per device, so a saved voice that is missing falls back to Automatic. `SB.applyVoice` also sets the utterance language to the voice's language, because browsers often ignore the chosen voice otherwise. The Voice row shows which voice is speaking after a preview, or says it did not play.
- Settings also has a "Start over" group: *Reset all progress* (`SB.resetAllProgress`: every student's scores, streaks, and module data; profiles and settings stay) and *Erase everything* (`SB.eraseEverything`: all `studybuddy.v1.*` data including profiles and the PIN, then the page reloads as a new Guest). Both go through `SB.requirePin` with a confirm dialog that names the students.
- Stopping sound: pressing a speaker button that has `.playing`, pressing Escape, leaving the page, or turning Sound or Read aloud off calls `SB.stopAll()`, which stops tones and speech. The Atlas has its own speech code and registers `window.__sbStopHook` so it stops too.
- Info pages (Help, FAQ, About) are plain writing for admins and students. The site may be shared publicly, so keep the privacy wording accurate: nothing is sent anywhere, and everything is saved in the browser.

## 6b. Onboarding (Guest first)
- No setup screen. `SB.ensureGuest()` makes a profile named Guest (`guest: true`) on the first visit, from the hub or straight from a module link (`SB.requireProfile`).
- Invite: `SB.result()` calls `maybeInvite()` after a finished round. It shows only for a Guest, at most once per browser session, and never during the week after "Not now".
- `SB.nameDialog(onDone)` renames the Guest, keeping its progress, or with `{ add: true }` adds a person. The header chip "Guest · Add a name" opens it on every page.
- PIN: `SB.requirePin` offers a PIN with Skip the first time a protected action happens (`pinOffered`). `SB.afterProfileAdded` offers once more when there are two people (`pinOfferedAtTwo`). Without a PIN, protected actions just run, and the admin area shows a "No admin PIN yet" note with a Set a PIN button.
- "Who's studying?" shows only with two or more profiles. With one, the hub opens straight to the subjects.

## 7. Making a module from photos of a study guide
1. Read every photo. Put the content in `data.js`, keeping the teacher's wording, because that is what the test uses. Note the source at the top of the file.
2. Anything the guide points to but the photos don't show (class notes, charts, maps) is either left out, or added from general knowledge and marked in the app ("check against your class chart"). Then ask the owner for photos of those pages.
3. Build the tools from the shared builders: a study guide, `SBT.flashcards`, `SBT.quiz`, `SBT.sort`, plus anything the test format needs (Ancient Rome has Fill it in and Explain it).
4. Have a separate reviewer compare `data.js` with the photos before shipping. Fix any contradictions and ambiguous items.
5. Write a `_dev/tests/<module>_test.py` that plays every tool with the right answers from `data.js`.

## 8. Ancient Rome notes
- Source: the three-page "Ancient Rome Test 1: Study Guide". The gods list is the standard 12 Roman Olympians, marked in the app to check against the class chart. The Mediterranean map places are not in the module yet (the photos didn't include the map).
- Explain it checks answers with keyword groups (`EXPLAIN[].ideas`), plus a complete-sentence check. The score counts the first check only. Students can check again to learn.

## 8b. Handwriting notes
- `Pad` in hw.js has two stacked canvases: the paper with the gray guide, and the ink. Pointer events cover pen, touch, and mouse. Pen pressure changes line width, and coalesced events keep strokes smooth. Once a pen is seen, touches are ignored (palm rejection) until "Finger: on".
- Strokes are stored relative to the pad width, so a resize or rotation redraws them.
- Grading: at quarter size, recall = how much of the glyph is covered by thickened ink, and precision = how much ink lands on the thickened glyph. A pass needs recall ≥ 0.62 and precision ≥ 0.7. Missed glyph pixels are drawn in orange.
- Letters records distinct letters passed (out of 52). Words and Sentences are rounds (6 and 4). Practice paper is ungraded and can trace any typed text.

## 8c. Place Value and Zeros notes
- Problems are made by `gen.js` (`MATHGEN`), not stored. Numbers are handled as strings so decimals never pick up floating-point errors. Wrong choices are compared by value, so 7.5 and 7.50 can never both appear.
- `math_gen_check.mjs` checks the generators with BigInt math. Run it after any change to `gen.js`.
- Multiply, Divide, and Powers use `SBT.answer` with `kind: 'number'`, so commas are optional.

## 8d. The Planets and The Periodic Table notes
- Planet numbers are rounded from NASA's Planetary Fact Sheet. Moon counts for the giant planets keep changing, so they are written as "more than ...". Recheck them now and then.
- The periodic table data has one line per element (number, symbol, name, family, group, period). Elements 109–118 are "unknown properties". The study guide shows "How the table works" in the table's empty top area until an element is tapped.
- Both modules' content was fact-checked by a separate pass.

## 8e. Black Beauty notes
- Organized by Beauty's homes and the book's four parts (Part 1 ch. 1–21, Part 2 ch. 22–31, Part 3 ch. 32–45, Part 4 ch. 46–49), not chapter numbers, so it works with any edition.
- Content was fact-checked against the novel by a separate pass. Where the book is uncertain (Ginger's death), the text says "believes".

## 9. Parts of Speech notes
- Content is in `data.js`: the 8 `PARTS`, `SORT_WORDS` (words that nearly always do one job), `SENTENCES` (everyday), and `TRICKY` (words that switch jobs, for Label the sentence). Sentences are `word/tag` pairs.
- Grade-school conventions: articles (a, an, the) and number words count as adjectives; helping verbs are verbs. Content avoids possessives (my, his), this/that, and "to" + verb, because books disagree on how to label them.
- The content was reviewed by a separate pass for label accuracy. Re-review it whenever sentences are added.

## 10. Greek and Latin Roots notes
- Its own subject (`roots`, shown as "Greek and Latin Roots") with this module as the only entry. The module has no tags, so it never appears in another subject's Suggested area.
- Content is in `data.js`: `ROOTS` (18 roots: root, language, meaning, level, 2-3 words, a kid-friendly note, an example sentence, accepted typed answers, and the stems Explain it looks for), `TWO` (Insane words built from two roots), and `SORTS`. The list of roots and their meanings is the owner's. The words, notes, and two-root words were written for this module and fact-checked by a separate pass (ambi and amphi are cousins; the note says "remember amphi = both or around (Greek), ambi = both (Latin)").
- Levels: Easy = animal roots (7), Medium = bird roots plus malus, omnis, ex, eu (6), Hard = amphi, ambi, archos, kyklos, circum (5), Insane = words built from two roots. Quiz and Type the answer have a level picker. The Insane questions show the meaning of the second root, so the student has to recall what the listed root means.
- Mastery is per root and shared by Quiz and Type the answer. A root is mastered when at least 80% of its last 5 tries were right the first try (no hint, no second try) and it has had at least 3 tries. The module page shows "Roots mastered X of 18". The tool score sent to the hub is the number of roots mastered out of 18 (registry `masterAt: 18`). Saved in the module state: `roots` (last 20 tries per root), `missed`, `level`.
- A missed root is asked first in the next round (the quiz takes `keepOrder: true` so the module's order is kept), and small level pools repeat it within a round. Wrong choices never include a near-identical meaning (amphi, ambi, circum, and kyklos are never offered together).
- Study guide: all 18 roots by level with words and notes (and speaker buttons), the two-root words, and a Greek or Latin page. It gives no credit.
- Quiz and Type the answer have a "Skip, review later" button (`skip: true` in the shared tools): it shows the answer, gives no point, and records a miss, so the root is marked for review and comes back first in the next round.
- Flashcards are practice only. Sort it has three sets (animals, good/bad/around, Greek or Latin).

## 11. US States notes
- A Geography module (`modules/geography/us-states/`), no tags. Content is in `data.js`: `STATES` (50 records: name, capital, year admitted, order admitted with 1 = Delaware and 50 = Hawaii, motto, state bird, state flower, 3-4 notable cities that are not the capital, and optional `mottoNote` / `flowerNote` where a state has no adopted motto or a second official one) and `FLAGS` (50 simplified SVG drawings, one per state). The flags are drawn by hand: stripes, stars, and colors are exact where possible, and the detailed state seals are simplified, so they are recognizable but not exact.
- Facts were checked by a separate pass against Wikipedia's lists of state mottos and flowers and official sites. Georgia's motto is on its state seal but not officially adopted; Washington's is also seal-only; North Dakota and South Carolina have a second official motto (shown as a note). Tennessee's iris is the state cultivated flower.
- Tools: Study guide (six sections with a find box) and Flashcards are practice only. Quiz (Mixed, Capitals, Flags, Mottos, Birds, Flowers, Cities, Admitted) and Type the answer (Capitals, Name the state, Flags, Birds, Flowers, Years, Order) both have a topic picker (saved in `state.topic`) and a Skip button; Put in order has three sets (all 50, the first 13, the last 10) and uses 6 states per round. Mastery is the registry default (best round of 8 of 10, or 80% in place for order).
- Questions never ask "which state has this bird or flower" because many states share them. A "which state?" city question is only asked for a city name that appears once in the data. Wrong choices never repeat the right answer.
- `quiz` takes an optional `html` field per question (extra markup such as a flag). The test hook `window.__usTest` exposes the question builders so `us_states_test.py` can check every state.
- **Map tools (added after the owner asked that US States match the South America module).** `us-map.js` ports the Explorer's Atlas tools to the 50 states: Study map, Listen and tap (10 per round, mastered at 8), Find it (60 seconds, mastered at 20 found, best score saved), Drag names (all 50, mastered with 5 misses or fewer, three map styles), and a "Map shapes" flashcard deck (whole country, one state colored). They behave like the Atlas: zoom and pan, Tab/Enter on every state, names spoken only from speaker buttons (or Read aloud), generic aria-labels on the game maps.
- Outlines are in `mapdata.js`, generated by `_dev/us-map/geo_us.mjs` from the US Census 1:10m TopoJSON (`_dev/us-map/us-10m.json`, via vega-datasets). It uses a hand-written Albers USA projection (Alaska and Hawaii as insets), simplifies the lines, finds each state's label spot, and colors states so neighbors never match (4 colors). Rerun `node study-buddy/_dev/us-map/geo_us.mjs` to regenerate. Small northeastern states (VT, NH, MA, RI, CT, NJ, MD, DE) are labeled in the ocean with a leader line; DC is drawn as context only.
- **Standing rule: every geography unit from now on is based on the South America module** (Study guide where useful, Study map, Flashcards with a map-shapes deck, Listen and tap, Find it, Drag names, plus the unit's own quiz tools) unless the owner says otherwise.

## 12. Phonograms, Black Beauty (study guide version), archiving, and Refresh for the latest
- **Archiving a module.** Add `archived: true` (and an optional `archivedNote`) to its registry entry. It stays on disk, keeps its saved progress, and still opens by direct link, but it leaves the hub, search, and the progress totals. The admin area has an **Archived** tab that lists archived modules with an Open link and each student's mastered count. The first Black Beauty (`black-beauty`) is archived and titled "Black Beauty (old version)".
- **Black Beauty** (`black-beauty-guide`, `modules/english/black-beauty-guide/`) is built from the teacher's study guide PDF (section 7). `data.js` holds `CH` (every chapter's questions and answers in the guide's wording; checkpoint and homework flags; Part 1 ch. 1-21, Part 2 ch. 22-31, Part 3 ch. 32-44, Part 4 ch. 46-49), plus `QUIZ`, `TYPE`, `EVENTS`, and `EXPLAIN` (the guide's answers are the model answers). The guide has no chapters 38, 39, or 45 and repeats 25, 28, 29, 36, and 37 (each kept once); the study guide says so. Where the guide asks a bare "Why?", the module adds a few words in brackets so the question stands alone. Tools: Study guide, Flashcards, Quiz, Put in order, Type the answer, Explain it.

## 17. Review fixes (October 2026)
- **Old Safari:** no regex lookbehind (`(?<=`, `(?<!`) anywhere in site code; Safari before 16.4 rejects the whole file. `review_fixes_test.py` checks this.
- **Best score:** `SB.result` keeps the best *share* of a round (6/6 beats 7/9), so tools whose sets differ in size keep their Mastered state.
- **Saving:** a failed `localStorage` write shows one "out of room" toast per page. Scratch pad profile notes share a device-wide cap (2.4 MB).
- **Dialogs:** `SB.confirm({ danger: true })` focuses Cancel (`data-autofocus`).
- **Hub:** `route()` calls `SB.applyDisplay()` so a student switch shows that student's display options.
- **Backups:** `exportAll` leaves out keys of deleted students; `checkBackup` drops such keys instead of rejecting the file.
- **Offline worker** (`_dev/sw.template.js`): installs with `cache: 'reload'`, fetches with `cache: 'no-cache'` (a cheap 304 when unchanged), falls back to the saved copy after 4 seconds, falls back to `index.html` only for page loads, and answers audio `Range` requests with a proper 206 from the saved file. "Refresh for the latest" downloads the new file list before clearing anything.
- **Answer checking:** `SBT.judge(item, value, kind, opt)` is the typed-answer judge on its own (tested directly). Fraction answers accept thousands commas, `1-3/4`, `1 and 3/4`, ½-style symbols and the fraction slash; a terminating decimal of the right value returns the `decimal` nudge (no try used). For number and fraction answers a trailing unit word is stripped and the answer accepted with "No units needed next time". Text answers turn off autocorrect.

- **Atlas:** `speakText()` waits 80 ms after `cancel()` (Chrome drops an utterance that follows it at once). Listen and tap is locked during the 0.9 s pause and holds the next name if the tab changes (`lsPause`/`lsResume`). Flashcards read the card's question when Read aloud is on. A deck counter stops a stale answer timer from marking a card in a new deck.
- **Ham:** module state keeps `missed` (question ids missed on mock exams, newest 150), `cardSec` (last flashcard section, via the new `SBT.flashcards` `onSection` option) and `examNow` (an unfinished exam, offered back on the start screen).
- **Handwriting:** one credit per pass; Check hides after a pass.
- **Larger text:** CSS heights use `var(--vh, 100vh)`; `sb-core.js` sets `--vh` to `100vh / 1.15` under `html.sb-large`, because `zoom` on the body makes `100vh` 15% too tall inside it.
- **Accessibility:** module tabs are a roving-tabindex tab list with arrow keys and `aria-controls`; dialogs make the rest of the page `inert` and trap every focusable kind; the hub focuses the new page's `h1` after a route change; flashcards hide the turned-away face (`aria-hidden`); sort chips expose `aria-pressed` and accept a detail-0 click; quiz feedback is `aria-live`; Put in order adds marks and screen-reader text; `.sr-only` is in `sb.css`. A speaker button with a recorded clip shows even without device speech.

The math check is seeded (`SEED=`), its operator and shown-number checks are live again, multiple-choice options must differ in value, and every generated answer is typed back through `SBT.judge`. `.github/workflows/check.yml` runs on pull requests (build committed, math check, all tests); `deploy.yml` waits until the live `sw.js` carries the new version. Settings, Updates shows this device's version (its cache name) against the live one.

## 24. Stacked fraction answer boxes (October 2026)
- **Boxes, not a text box:** `SBT.answer` with `kind: 'fraction'` draws `SBT.fracBox('Your answer')`: `span.fbox` holding `input.fx-w` (whole number), then `span.fstack` with `input.fx-n` (top), `span.fline` and `input.fx-d` (bottom). Digits only (`inputmode=numeric`, non-digits stripped as typed), max 7 digits for the whole box and 5 for top and bottom; a box over 3 digits widens itself. The classes are `fx-*` because `.fn`/`.fd` already mean the display spans inside `.frac`.
- **Text bridge:** `SBT.wireFrac(root)` gives each `.fbox` a `value` property that reads as `"1 3/4"`, `"3/4"`, `"2"` (or `"3/"` while the bottom is missing) and can be set from the same text. So `judge()`, `parseFrac()` and the calculators did not change. Slash typing and decimals are no longer possible; the decimal nudge in `judge` is kept but unreachable.
- **Answer flow:** a top without a bottom (or the reverse) gets a hint and is not a try; all boxes empty says "Fill in the boxes first." The error box turns the boxes red through `.fbox.bad`. First focus is the top box, or the whole box when the item's `form` is `mixed`. The on-screen keypad and the "You typed" preview were removed (the boxes are the preview).
- **Fractions in text:** `SBT.stackText(text)` escapes text and draws `n/d` and `w n/d` as stacked fractions (`span.frac` / `span.mixed`, each carrying `data-s` with the plain text). It is used for the explanation (`steps()`), the hint and error line, the "Answer:" in the review list, and the calculators' worked steps. ## 38. Typing: Learn the Keys (October 2026)
The owner asked for a typing tutor based on keybr.com, as its own subject. The plan is in the Claude Project as `study-buddy/TYPING_TUTOR_PLAN.md` (five phases). Phase 1 is built: the shared typing engine, the **Typing** subject (`typing` in `registry.js`), and the module **Learn the Keys** (`modules/typing/learn-keys/`). Drills, Tests, and Games come in later phases and reuse the same shared files.
- **Owner decisions:** target speed 15 WPM for every student by default (changeable per student on the Lesson tab); a wrong key does not move on ("Fix mistakes: on", changeable); Key Hunt for the youngest is in phase 1; games will be Key Hunt, Word Sprint, Falling Words, and Ghost Race.
- **`shared/sb-typing-gen.js` (`SBTG`)** has no page code, so `gen_check_typing.mjs` loads it in Node. `ORDER` is the course: `a s d f j k l` open at the start (`START` = 7), then g h e i r u t y o n w m c b v x p q z, one letter at a time. The course is the 26 letters; capitals, punctuation, and numbers belong to the Drills phase. `;` is shown on the home row but is not part of the course.
- **Opening letters:** each key keeps its last 30 keystrokes as `[ms, hit]` (`addRound`). `ms` is the time since the key before it, capped at 3 seconds (so slow hunt-and-peck presses count as slow, not skipped); it is 0 for a mistake or the first key of a round. A key is *ready* with 10+ samples, 95%+ right, and an average speed at or above the target (WPM = 12000 / ms). The next letter opens when every open letter is ready (`canUnlock`). The *focus* letter is the weakest open letter (`focusKey`, ties go to the newer letter). Spaces are not counted.
- **Lesson text** (`lessonWords`): 12 words. More than half of them carry the focus letter, and it always shows up at least 3 times (in practice it is 11 to 18% of all letters). Real words come from the list when enough fit (share 15% to 75% depending on how many real words use only open letters, less when few real words have the focus letter); otherwise made-up words from a three-letter model of the word list. Made-up words avoid letters three times in a row, rare doubles ("kk"), and words with no vowel. No word repeats within four words.
- **Word list:** `_dev/typing/words.txt` (3,249 words, most common first) comes from Josh Kaufman's google-10000-english list (no swears, US), filtered and then reviewed word by word for children aged 4 to 10 (no abbreviations, proper nouns, British spellings, adult, violent, upsetting, or religious and political words, and little web or business jargon; everyday words like email, online, and click stay), plus about 110 easy words for the early letter sets. A second review removed 40 more. `python3 _dev/typing/make_words.py _dev/typing/words.txt` writes `shared/sb-typing-words.js`. Do not edit that file by hand.
- **Blocklist:** `_dev/typing/blockhash.txt` holds 32-bit FNV-1a hashes of unkind words (from the LDNOOBW English list plus extra words, including look-alike spellings a reviewer found in made-up words; `gen_check_typing.mjs` keeps those as a regression list), so no bad words are written in the site or the repository. Real words are checked whole; made-up words are also checked for a blocked word hidden inside them (any 3 to 8 letter piece).
- **`shared/sb-typing.js` (`SBTY`)**: `keyboard(host, { rows: 'full'|'letters', zones, onTap })` draws a US QWERTY SVG keyboard. Keys have ids for the characters they type (`' '` is the space bar) and classes for finger zones (`z-lp` ... `z-rp`, `z-th`), `off` (dimmed), `ready`, `focus`, `next`, `hint`, `sel`, `hit`/`miss` flashes, and `h0`-`h4` for heat maps. `typer(host, { text, wait, onKey, onDone })` shows the text (each word in a no-wrap group, so lines break only at spaces) and scores the round: `{ chars, correct, presses, wrong, elapsed, wpm, acc }`. WPM counts five characters as a word, and each gap between keys counts at most 3 seconds.
- **Reading keys:** one `keydown` listener on the page sends keys to whichever typing tool is on screen (`SBTY.take(handler)`; each tool takes it again in `enter()`). It ignores keys while a dialog is open, while another text box or menu has focus (the Lesson's Target speed menu gives focus back after a change), and with Ctrl, Alt, or Command. It stops the space bar scrolling and stops held keys repeating. A capital where the small letter is wanted (Caps Lock or Shift) is not counted; a message says why. A letter fixed with Backspace (Fix mistakes off) still counts as a mistake. A handler can also take `named(k)` for Shift, Enter, Caps Lock, Backspace, and Tab (the Keyboard map uses it; Tab still moves focus). Typing pages set `window.SB_NO_SLASH_SEARCH` so "/" is a key, not the search shortcut. Phones and tablets with only an on-screen keyboard (`SBTY.needsKeyboard()`: coarse pointer and no fine pointer) get a notice, and tapping the text focuses a hidden box whose `input` events type instead (only letters added since the last event count, a shorter box is Backspace, and the box empties after each space, so keyboards that build up a whole word do not type letters twice). Tapping a key in the Lesson's keyboard picture types it too.
- **Tools:** *Lesson* (`masterAt: 26`; each round records letters open out of 26; a round at 90%+ accuracy counts once toward the daily goal), *Key Hunt* (for the youngest: find a letter on a big keyboard, by key or by tapping; Home row, Top row, Bottom row, or All letters; Capitals (on by default, owner's choice) shows the letter as it looks on the keys, and turning it off shows the small letter; no timer; a wrong key outlines the right key and names the finger; first-try right answers give credit; only letter keys count; leaving the tab pauses the round; messages and speech say "the letter A"; `masterPct: 0.9` of 10), *Keyboard map* (study: finger colors, press or tap any key, including Shift and Enter, to see its finger, how to sit and use the home row), *Key stats* (study: letters open, best round, the last 10 rounds, a speed or accuracy heat map, and a box per open letter).
- Speeds show as "words a minute" (not WPM) for the children.
- **Saved state** (`SB.moduleKey('learn-keys')`): `{ unlocked, stats: { <letter>: [[ms, hit], ...] }, target, wait, showKb, rounds: [{ at, wpm, acc }] (last 50), best, hunt: { set, caps } }`. Only totals are kept, never what was typed. Later typing modules can read this key for the student's target speed and key stats.
- **Colors:** `sb-typing.css` adds tokens with light and dark values: `--fz-p`, `--fz-r`, `--fz-m`, `--fz-i`, `--fz-t` (finger zones), `--heat0`-`--heat4` (weak to strong), and `--key`, `--key-line`.
- **Tests:** `typing_test.py` types real rounds key by key (right keys, wrong keys with Fix mistakes on and off, Backspace, a letter opening, results and credit, "/" not opening search), plays Key Hunt (hint, tapping, result, rows, Capitals), checks the Keyboard map fingers, Key stats, dark mode, the phone notice and on-screen typing, and layout at 1440x900, 1280x720, 360x740, and 915x412. `gen_check_typing.mjs` checks the course order, the word list, and 8,000+ lessons at every stage and focus letter (open letters only, no blocked words, focus letter coverage, no repeats), plus the stats, unlocking, and scoring rules.

## 39. Typing Drills (October 2026)
Phase 2 of the typing plan: the module **Typing Drills** (`modules/typing/drills/`, `drills.js`), built on the section 38 engine.
- **Tools** (registry order): *Rows* (easy: Home, Top, Bottom, or Number row; keys off the row are dimmed), *Common words* (medium: 25 words from the 100, 300, or 1,000 most common words for kids; "i" shows as "I"), *Capitals and punctuation* (medium: capitalized common words, or words with , . ? ! ; : ' " - ( ), contractions, and hyphenated words), *Weak keys* (medium: 16 words built around the student's three weakest letters, named in the goal line: most missed first, then slowest, counting only letters typed 10 or more times unless fewer than three qualify), *Sentences* (hard: three sentences, or three with numbers), *Paragraphs* (insane: one paragraph; wrong keys move on and Backspace does nothing).

Each tool keeps a best per choice in the module's state (`{ opt: { <tool>: <choice> }, best: { "<tool>:<choice>": { stars, wpm, acc } } }`). The results line lists the keys missed ("Keys to practice"). Accuracy shows rounded down, so 100% means no mistakes (Learn the Keys does the same).

Resetting Typing Drills does not touch them (resetting Learn the Keys does). Learn the Keys re-reads those four fields from storage before every save (`sync` in `lk.js`), so an open Learn the Keys tab never erases drill practice, and both pages reload when shown again from the back/forward cache. Weak keys uses the letters open in Learn the Keys plus any letter typed at least 10 times; with no typing yet it asks the student to do a few rounds first.
- Coming back to a tab starts fresh text if the round has not begun (so Weak keys picks up new practice). Changing Fix mistakes takes effect from the next key, without restarting the round. The Target speed menus are marked `data-typing`: a typing key pressed while the menu has focus leaves the menu and types. Long text fades at the bottom when more is below.
- **Keyboard:** capitals and shifted symbols light up the key and the Shift on the other hand (`SBTY.keysFor`). The number row, Capitals and punctuation, sentences with numbers, and Paragraphs show the full keyboard; the others show the letter rows. Tapping a key in the picture types it.
- **Generators** (in `sb-typing-gen.js`): `rowDrill` mixes real words that use only that row (home and top rows) with key groups like "fjfj" (never three of a key in a row, checked against the blocklist), adding ; on the home row and , . on the bottom row; `numberDrill` uses every digit at least once (two to four digit numbers, years, and pairs like 3-7); `capitalsDrill` and `punctDrill` use common kid words of 3 to 8 letters; nothing repeats within three items.

Phase 3 (Tests) will reuse it.

## 40. Speed and Accuracy Tests (October 2026)
Phase 3 of the typing plan: the module **Speed and Accuracy Tests** (`modules/typing/tests/`, `tests.js`).
- **Speed test** (medium, `masterAt: 20`): 30 seconds, 1, 3, or 5 minutes, at Easy (common kid words), Medium (sentences), Hard (sentences and number sentences), or Insane (paragraphs; wrong keys move on and Backspace does nothing). The other levels follow the shared Fix mistakes setting. The clock starts with the first key; there is enough text for 130 words a minute. When time is up the results replace the text: speed (right keys / 5 per minute of the test), raw speed (every key), accuracy, steadiness (`SBTG.consistency`: 1 minus the spread of the 5-second speeds compared with their average, leaving out a step shorter than 5 seconds), and a one-line chart of words a minute in each step (`SBTG.speedSteps`; a last step under 2 seconds joins the one before, so finishing early cannot draw a false spike). The chart is drawn on a time axis at the width of its box and redrawn when that changes, so its labels stay readable on a phone; it has a 2px line in `--teal-ink`, a y-axis in steps of 20, a crosshair and readout on hover over the whole step, and a hidden table for screen readers. Keys typed after time is up end the test and do not count; with Fix mistakes off, a key undone with Backspace no longer counts as right, while raw speed counts every key pressed. Finishing the text early says "Done!" instead of "Time!". Switching to another browser tab or app mid-test starts it over. A test of 1 minute or more at 90%+ records its speed, rounded down, with `ctx.result(wpm, null)` and counts once toward the daily goal; otherwise it records 0. "Same text again" reuses the seed. Leaving the tab mid-test starts it over. Focus goes to the result line, not the Try again button, so a space typed after time is up cannot start a new test.
- **Accuracy test** (hard, `masterPct: 0.97`): Easy 20 common words, Medium or Hard about two sentences, Insane one paragraph. A wrong key has to be fixed; the score is accuracy in whole percents (`ctx.result(score, 100)`), and 95%+ counts toward the daily goal. On Insane the first mistake ends the test, the score is the share of the paragraph typed, and the missed key is named and added to the letter stats. The text stays on screen so the mistakes can be seen.
- **Your own text** (study): paste or type up to 2,000 characters; `SBTG.cleanText` makes it typeable (plain quotes and dashes, accents dropped, letters like ß and æ spelled out, all line breaks become spaces, keyboard characters only, long text cut at a space). Text with fewer than 5 typeable letters (another alphabet, only symbols) gets a message saying so. Words longer than 18 letters (or links) may break across lines. The text is kept for next time. No score.
- **Saved state:** `{ speed: { len, level, best: { "<seconds>:<level>": { wpm, acc } }, history (last 30) }, acc: { level, best: { <level>: { score } } }, custom }`. Letters typed in every test go into the shared letter stats (`SBTY.addStats`). The shared settings helpers (`SBTY.shared`, `saveShared`, `addStats`) now live in `sb-typing.js` and Typing Drills uses them too. `typer.snapshot()` gives the round so far for tests that end before the text does.
- **Tests:** `typing_tests_test.py` types real keystrokes with the page clock fast-forwarded (`performance.now` offset) and checks scores, the chart and hover, mastery and credit, history and bests, Same text again, the space-after-time rule, Insane rules, leaving the tab, the Accuracy test and its Insane stop, Your own text, and layout (1440x900 and 1280x720 with no scroll, including the results; 360px and 915x412 with no sideways scroll). `gen_check_typing.mjs` checks the test text at every level and length, the timed scores, the 5-second steps, steadiness, and text cleaning.

## 41. Typing Games (October 2026)
Phase 4 of the typing plan: the module **Typing Games** (`modules/typing/games/`, `games.js`). All three tools are `kind: 'study'` (the owner's plan: games are practice, with no credit or mastery), and each keeps the student's best score per level in the module state (`{ sprint: { level, best: { <level>: words } }, fall: { level, best }, ghost: { speed, best (words a minute), wins } }`). Calm by design: no mascots, no flashing, no sounds while playing. Words come from `SBTG.gameWords(level)`: Easy short sight words (2 to 5 letters from the first 200 kid words), Medium common words (3 to 7 letters from the first 1,000), Hard longer words (6 to 10 letters, some capitalized). Key Hunt stays in Learn the Keys.
- **Word Sprint** (easy): one big word at a time with the next three shown; 1 minute, starting with the first key; a word counts when its last letter is typed, and no space is needed (a space is ignored, not a mistake). Fix mistakes on (the shared setting): a wrong key is marked and has to be fixed; off: the letter is skipped, shows red, and the word does not count. The result gives the number of words. Leaving the tab, or switching to another browser tab, mid-game starts it over (switching browser tabs says so).
- **Falling Words** (medium): words fall from the top of a play area (sized from `--vh` and `--chrome`, with a floor of 260px). The first key picks the lowest word starting with that letter, and Backspace steps back; a new word never starts with the same letter as a word already falling, and words fall in side-by-side lanes so they do not cover each other. A word reaching the bottom uses one of three misses; the third ends the game. Speed and how often words appear grow a little with each word cleared, capped per level so Easy stays calm (Easy: at most 1.3 times the starting speed and a word every 1.8 seconds; Medium 1.6 times and 1.3 seconds; Hard 2 times and 1 second). Leaving the tab or the browser tab pauses with a Keep going button (focused, so Enter or Space keeps going). With the device's reduce-motion setting, words move in steps of about 24px instead of gliding. Animation uses `requestAnimationFrame` with each frame's step capped at 250ms.
- **Ghost Race** (medium): three sentences; the ghost starts with the first key and types at a steady speed: "Your best" (the student's best race at 90%+ accuracy and no more than 150 words a minute, so pasted or predicted text cannot set an impossible ghost; their target speed before any race) or 10, 15, 20, 30, or 40 words a minute. The ghost's place shows as an orange underline in the text (`typer.ghost(i)`, new in `sb-typing.js`) and as a second progress bar beside "You". The result takes the text's place (so it fits the screen) and says who won and by how many seconds, or a tie; races won are counted. The bars update only when a whole percent changes.
- In Word Sprint and Falling Words, a capital typed where a small letter is wanted (or the reverse) shows a Caps Lock or Shift message instead of counting as a mistake. One page-level `visibilitychange` listener calls each game's `_hide`, so Reset does not add listeners. The reduce-motion setting is read once and kept up to date with a `change` listener.
- After a game ends, focus goes to the result line, not the Play again button, so keys typed just after the end cannot start a new game.
- **Tests:** `games_test.py` plays each game with real keystrokes, using a fast-forwarded page clock (`performance.now` and `requestAnimationFrame` times shifted) for the minute limit, falling, and the ghost; it checks scores, bests, Fix mistakes, keys after the end, levels, distinct first letters, pausing, reduce motion, ghost wins and losses, that games record no results, and layout at 1440x900, 1280x720, 360x740, and 915x412. `gen_check_typing.mjs` checks the game word lists at every level.
