# Study Buddy: Architecture and Working Agreement

Read this first when continuing the project. Then read `STYLE_GUIDE.md` for the look, and `BUILD_APPROACH.md` for how Explorer's Atlas (the first module) was built.

## 1. Owner's rules (standing)
- Build only modules the owner asks for. Empty subjects stay empty.
- Parent-led tool. Everyone sees every module. Subject filters, no assigning.
- No emoji. The presentation never changes by age: the same look for every child. Friendly comes from the design system, not from cartoons.
- Difficulty is Easy / Medium / Hard / Insane, never grade levels.
- Hide unused features rather than deleting them.
- Explorer's Atlas: don't change Study map, Drag names, Find it, or Listen and tap unless asked. Flashcards show the whole continent, and their sound plays only from the speaker button. Quiz questions are never read aloud.
- Test at 1440×900 with no scroll bars on tool screens, and with no sideways scroll at phone width (360px, Galaxy S23).
- Deliver code as downloadable files.

## 2. Vocabulary
Study Buddy → **Subjects** → **Modules** → **Tools**.
- A module has one home `subject` and a list of `tags`. A module whose tags include another subject's id shows in that subject's **Suggested** area.
- Each tool has a `difficulty`. A module's difficulty is the range of its tools, computed automatically (`SB.difficultyRange`).

## 3. Files
| Path | Role |
|---|---|
| `index.html` + `hub.js` | Hub pages, routed by hash: `#/` who's studying, `#/home[/subject]`, `#/module/<id>`, `#/parent[/progress\|children\|backup\|pin]`. First run (no profiles) shows setup. |
| `registry.js` | `window.SB_REGISTRY = { subjects, modules }`. A JS file (not JSON) so it also loads from `file://`. |
| `shared/sb.css` | Tokens and components from the style guide, plus hub-only classes. New modules link it. |
| `shared/sb-core.js` | `window.SB`: profiles, storage, progress, settings, tones, speech, toast, dialogs, PIN, backup, service-worker registration. |
| `modules/<subject>/<module>/index.html` | One page per module. It may be a built file (the Atlas is built from `_dev/atlas-src`). |
| `sw.js` | Generated by `node _dev/build.mjs` from `_dev/sw.template.js`. Network-first with an offline cache; the version changes when any file changes. |
| `_dev/` | Source, build script, tests, docs. Not part of the running site. |

Build after any change: `node _dev/build.mjs` (assembles the Atlas and rewrites `sw.js`). Test: `python3 _dev/tests/hub_test.py` and `python3 _dev/tests/atlas_test3.py`.

## 4. Saved data (localStorage, all under `studybuddy.v1`)
| Key | Contents |
|---|---|
| `studybuddy.v1.root` | `{ profiles:[{id,name,color}], active, pin (hash), pinRemovedAt }` |
| `studybuddy.v1.child.<id>` | `{ settings:{sound, readAloud}, streak, bestStreak, daily:{d,n,done}, tools:{ "<module>/<tool>": {attempts, visits, best, max, lastScore, last} }, last:{module,tool,at} }` |
| `studybuddy.v1.m.<childId>.<key>` | A module's private state. Get the key from `SB.moduleKey('<key>')`, and list `<key>` in the module's `storage` array in the registry. |

Mastery is computed when the data is read, from registry rules: `masterAt` (best ≥ n) or `masterPct` (best / max ≥ share, default 0.8). Changing a rule later re-grades old scores automatically.

The daily goal (20 right answers) and the streak are per child and shared across all of Study Buddy. Module-specific rewards (the Atlas passport) stay inside the module.

## 5. Module contract
A module page must:
1. Load `shared/sb-core.js` with a relative path (e.g. `../../../shared/sb-core.js`), and link `shared/sb.css` (unless it brings identical CSS, like the Atlas).
2. Call `SB.requireProfile()` on load. It returns the child, or sends the page back to the hub.
3. Save its own state under `SB.moduleKey(...)`.
4. Use the standard header: an eyebrow linking back (`‹ Study Buddy · Subject`), the module title, a child chip (`SB.avatar(kid)`), and streak and today pills.
5. Use one tab per tool, with tab ids matching the registry tool ids. Open the tab given in `?tool=<id>`.
6. Call `SB.opened(module, tool)` when a tool opens, `SB.credit()` / `SB.slip()` on each answer, and `SB.result(module, tool, score, max)` when a round finishes.
7. Use `SB.sfx` for tones and `SB.say(text)` for read-aloud (it respects the child's Read aloud setting, which is off by default). Speaker buttons use `SB.sayButton(text)` and always play.
8. Put destructive actions behind `SB.requirePin(message, onOk)`.
9. Keep working when `window.SB` is missing, if it's practical (the Atlas does).

Then add an entry in `registry.js`, rebuild, and run the tests.

## 6. Notes and caveats
- The parent PIN is a hash stored locally. It is a kid lock, not security. "Forgot PIN?" (type REMOVE) clears it and stamps `pinRemovedAt`, which the parent area shows.
- Progress is per browser, per device, per web address. Backup export/import moves it.
- Opened on its own, the Atlas logs one harmless "file not found" for `sb-core.js`, then runs standalone.
- The style guide says selected tabs are teal, but the real app uses navy. Study Buddy follows the app (navy).
- Phone fix in the Atlas (v3.1): the settings row now wraps under 760px. Before this, it scrolled sideways on phones. Desktop is unchanged.
