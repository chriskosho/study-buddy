# Study Buddy: Architecture and Working Agreement

Read this first when continuing the project. Then read `STYLE_GUIDE.md` for the look, and `BUILD_APPROACH.md` for how Explorer's Atlas (the first module) was built.

## 1. Owner's rules (standing)
- Build only modules the owner asks for. Empty subjects stay empty.
- Parent-led tool. Everyone sees every module. Subject filters, no assigning.
- No emoji. The presentation never changes by age: the same look for every child. Friendly comes from the design system, not from cartoons.
- Difficulty is Easy / Medium / Hard / Insane, never grade levels.
- Hide unused features rather than deleting them.
- Explorer's Atlas: don't change Study map, Drag names, Find it, or Listen and tap unless asked. Flashcards show the whole continent, and their sound plays only from the speaker button. The Atlas never reads quiz questions aloud. Its map activities can be used from the keyboard (every country takes Tab and Enter), and Say names follows each child's Read aloud setting (off by default).
- Other modules read questions aloud only when the child's Read aloud setting is on (off by default). Speaker buttons always work.
- Test at 1440×900 with no scroll bars on tool screens, and with no sideways scroll at phone width (360px, Galaxy S23).
- Deliver code as downloadable files.

## 2. Vocabulary
Study Buddy → **Subjects** → **Modules** → **Tools**.
- A module has one home `subject` and a list of `tags`. A module whose tags include another subject's id shows in that subject's **Suggested** area.
- Each tool has a `difficulty`. A module's difficulty is the range of its tools, computed automatically (`SB.difficultyRange`).

Every new module gets its own test file in `_dev/tests/`.

## 4. Saved data (localStorage, all under `studybuddy.v1`)
| Key | Contents |
|---|---|
| `studybuddy.v1.root` | `{ profiles:[{id,name,color,guest?}], active, pin (hash), pinRemovedAt, pinOffered, pinOfferedAtTwo, pinSkipped, inviteSnoozeUntil }` |
| `studybuddy.v1.child.<id>` | `{ settings:{sound, readAloud}, streak, bestStreak, daily:{d,n,done}, tools:{ "<module>/<tool>": {attempts, visits, best, max, lastScore, last} }, last:{module,tool,at} }` |
| `studybuddy.v1.m.<childId>.<key>` | A module's private state. Get the key from `SB.moduleKey('<key>')`, and list `<key>` in the module's `storage` array in the registry. |

Mastery is computed when the data is read, from registry rules: `masterAt` (best ≥ n) or `masterPct` (best / max ≥ share, default 0.8). Changing a rule later re-grades old scores automatically.

The daily goal (20 right answers) and the streak are per child and shared across all of Study Buddy. Module-specific rewards (the Atlas passport) stay inside the module.

## 5. Module contract
**The easy way (use this for every new module):** copy `modules/english/parts-of-speech/` as the pattern.
- `index.html` loads `shared/sb.css`, the module's own CSS, `sb-core.js`, `registry.js`, `sb-module.js`, then the module's `data.js` and script.
- The script calls `SBM.start({ module: '<registry id>', defaults: {...}, tools: { <toolId>: { init(ctx), leave?(), enter?() } } })`.
- **Flashcards are practice only.** They give no credit, streak, or mastery, and record no result (registry `kind:'study'`, blurb ends "Practice only."). Credit comes only from checked tools: quizzes, sort, order, type-the-answer, explain, and the Atlas games.
- Each tool fills `ctx.panel`, and calls `ctx.credit()` / `ctx.slip()` per answer and `ctx.result(score, max)` per finished round. It uses `ctx.say(text)` for questions (spoken only when Read aloud is on), `ctx.sayButton(text)` for speaker buttons, `ctx.state` + `ctx.save()` for saved data, and `ctx.sfx` for tones.
- Tool tabs come from the registry entry, in registry order. Tabs, the header, settings, Reset, and the phone layout are handled by the shell.
- Phone layout is built in: tabs become one swipeable row, and the header and settings get compact. Keep module CSS phone-friendly with a `@media (max-width:760px)` block.

**What any module page must do (the shell does all of this for you):**
1. Load `shared/sb-core.js` with a relative path (e.g. `../../../shared/sb-core.js`), and link `shared/sb.css` (unless it brings identical CSS, like the Atlas).
2. Call `SB.requireProfile()` on load. It returns the child, or sends the page back to the hub.
3. Save its own state under `SB.moduleKey(...)`.
4. Use the standard header: an eyebrow linking back (`‹ Study Buddy · Subject`), the module title, a child chip (`SB.avatar(kid)`), and streak and today pills.
5. Use one tab per tool, with tab ids matching the registry tool ids. Open the tab given in `?tool=<id>`.
6. Call `SB.opened(module, tool)` when a tool opens, `SB.credit()` / `SB.slip()` on each answer, and `SB.result(module, tool, score, max)` when a round finishes.
7. Use `SB.sfx` for tones and `SB.say(text)` for read-aloud (it respects the child's Read aloud setting, which is off by default). Speaker buttons use `SB.sayButton(text)` and always play.
8. Put destructive actions behind `SB.requirePin(message, onOk, onCancel, { confirm: { title, text, ok } })`. The `confirm` option makes the action always ask "Are you sure?" first, even with no PIN or when the parent area is unlocked. Escape and outside taps cancel.
9. Keep working when `window.SB` is missing, if it's practical (the Atlas does).

Then add an entry in `registry.js`, rebuild, and run the tests.

## 6. Notes and caveats
- The parent PIN is a hash stored locally. It is a kid lock, not security. "Forgot PIN?" (type REMOVE, then choose a new PIN) keeps the old PIN until the new one is saved, then stamps `pinRemovedAt`; the parent area shows a dismissible note on the Progress and PIN tabs. Backup files contain the PIN hash, so keep them private.
- Progress is per browser, per device, per web address. Backup export/import moves it. `SB.checkBackup(text)` validates a file before anything is written (app name, only `studybuddy.v1.` keys, profile ids and colors, typed child records), and `importAll` restores the old data if storage runs out. Another tab changing the active child reloads this one.
- Dialogs are named by their heading (`aria-labelledby`) and keep Tab inside. `.msg` feedback lines announce themselves (`aria-live`). Text colors use the `-ink` tokens and button fills the `-fill` tokens so contrast holds in light and dark mode (see STYLE_GUIDE).
- Opened on its own, the Atlas logs one harmless "file not found" for `sb-core.js`, then runs standalone.
- The style guide says selected tabs are teal, but the real app uses navy. Study Buddy follows the app (navy).
- Atlas phone layout (v3.2): every phone rule lives in one `@media (max-width:760px)` block at the end of the Atlas CSS. On phones the Study map list is one column, the prompt sits above the map in Find it and Listen and tap, and the names and feedback sit above the map in Drag names. Desktop is pixel-identical to v3 (checked with screenshot diffs at 1440×900 and 1000×800).

## 6a. Display options and swipe
- Per-child settings `theme` (light, dark, auto = match device), `font` (standard, dyslexic), and `size` (normal, large). `SB.applyDisplay()` sets `sb-dark`, `sb-dyslexic`, and `sb-large` on `<html>` as soon as sb-core.js loads. The Display button is gone: all display options now live on the Settings page (`#/settings`), reached from the header and footer of every page.
- Dark mode works through tokens in sb.css (`--surface`, `--navy-ink`, `--track`, `--tint-*`). New CSS must use tokens, never literal white, so it follows the theme. South America has its own `html.sb-dark` block (light mode is untouched).
- OpenDyslexic: sb-core injects the @font-face rules (with absolute URLs) and sets `--font`, so every page, including South America, switches font.
- Flashcard swipe: `SB.swipeCard(stage, card, { onRight, onLeft })`. Right = I knew it, left = Still learning, a tap flips, and the arrow keys work too. Used by `SBT.flashcards` and South America.

## 6c. Shell, Settings, voice, and stopping sound
- Every page loads `shared/sb-shell.js` and calls `SB.shell(...)`. Modules built with `SBM.start` get it automatically. The hub builds its trail per route (`hub.js route()`); `window.SB_SHELL_RELOAD` re-renders the shell after the child changes.
- Settings page: Theme, Font, Text size, Sound effects, Read aloud, Voice (with Preview), and a link to the parent area. Settings are per child and need no PIN; the parent area keeps its PIN. The voice list shows only this device's English voices. `voice` is a voice id from `SB.voiceId(v)` (the voiceURI, name and language, with a number added when a device lists several voices that are exactly alike), and `''` means Automatic. Android Chrome lists many voices with the same name, so `SB.voiceLabels` adds the voice code or a number to the names, and the Voice row says which voice code is speaking. `SB.voicesFor(lang)` ranks voices with `voiceScore` (Natural/Neural/Online/Google and common female voices up, David, Mark, compact, and espeak down); `SB.pickVoice` uses the saved voice if it applies to the language, otherwise the best one. Voices differ per device, so a saved voice that is missing falls back to Automatic. `SB.applyVoice` also sets the utterance language to the voice's language, because browsers often ignore the chosen voice otherwise. The Voice row shows which voice is speaking after a preview, or says it did not play.
- Settings also has a "Start over" group: *Reset all progress* (`SB.resetAllProgress`: every child's scores, streaks, and module data; profiles and settings stay) and *Erase everything* (`SB.eraseEverything`: all `studybuddy.v1.*` data including profiles and the PIN, then the page reloads as a new Guest). Both go through `SB.requirePin` with a confirm dialog that names the children.
- Stopping sound: pressing a speaker button that has `.playing`, pressing Escape, leaving the page, or turning Sound or Read aloud off calls `SB.stopAll()`, which stops tones and speech. The Atlas has its own speech code and registers `window.__sbStopHook` so it stops too.
- Info pages (Help, FAQ, About) are plain writing for parents and children. The site may be shared publicly, so keep the privacy wording accurate: nothing is sent anywhere, and everything is saved in the browser.

## 6b. Onboarding (Guest first)
- No setup screen. `SB.ensureGuest()` makes a profile named Guest (`guest: true`) on the first visit, from the hub or straight from a module link (`SB.requireProfile`).
- Invite: `SB.result()` calls `maybeInvite()` after a finished round. It shows only for a Guest, at most once per browser session, and never during the week after "Not now".
- `SB.nameDialog(onDone)` renames the Guest, keeping its progress, or with `{ add: true }` adds a person. The header chip "Guest · Add a name" opens it on every page.
- PIN: `SB.requirePin` offers a PIN with Skip the first time a protected action happens (`pinOffered`). `SB.afterProfileAdded` offers once more when there are two people (`pinOfferedAtTwo`). Without a PIN, protected actions just run, and the parent area shows a "No parent PIN yet" note with a Set a PIN button.
- "Who's studying?" shows only with two or more profiles. With one, the hub opens straight to the subjects.

## 7. Making a module from photos of a study guide
1. Read every photo. Put the content in `data.js`, keeping the teacher's wording, because that is what the test uses. Note the source at the top of the file.
2. Anything the guide points to but the photos don't show (class notes, charts, maps) is either left out, or added from general knowledge and marked in the app ("check against your class chart"). Then ask the owner for photos of those pages.
3. Build the tools from the shared builders: a study guide, `SBT.flashcards`, `SBT.quiz`, `SBT.sort`, plus anything the test format needs (Ancient Rome has Fill it in and Explain it).
4. Have a separate reviewer compare `data.js` with the photos before shipping. Fix any contradictions and ambiguous items.
5. Write a `_dev/tests/<module>_test.py` that plays every tool with the right answers from `data.js`.

## 8. Ancient Rome notes
- Source: the three-page "Ancient Rome Test 1: Study Guide". The gods list is the standard 12 Roman Olympians, marked in the app to check against the class chart. The Mediterranean map places are not in the module yet (the photos didn't include the map).
- Explain it checks answers with keyword groups (`EXPLAIN[].ideas`), plus a complete-sentence check. The score counts the first check only. Children can check again to learn.

## 8b. Handwriting notes
- `Pad` in hw.js has two stacked canvases: the paper with the gray guide, and the ink. Pointer events cover pen, touch, and mouse. Pen pressure changes line width, and coalesced events keep strokes smooth. Once a pen is seen, touches are ignored (palm rejection) until "Finger: on".
- Strokes are stored relative to the pad width, so a resize or rotation redraws them.
- Grading: at quarter size, recall = how much of the glyph is covered by thickened ink, and precision = how much ink lands on the thickened glyph. A pass needs recall ≥ 0.62 and precision ≥ 0.7. Missed glyph pixels are drawn in orange.
- Letters records distinct letters passed (out of 52). Words and Sentences are rounds (6 and 4). Practice paper is ungraded and can trace any typed text.

## 8c. Place Value and Zeros notes
- Problems are made by `gen.js` (`MATHGEN`), not stored. Numbers are handled as strings so decimals never pick up floating-point errors. Wrong choices are compared by value, so 7.5 and 7.50 can never both appear.
- `math_gen_check.mjs` checks the generators with BigInt math. Run it after any change to `gen.js`.
- Multiply, Divide, and Powers use `SBT.answer` with `kind: 'number'`, so commas are optional.

## 8d. The Planets and The Periodic Table notes
- Planet numbers are rounded from NASA's Planetary Fact Sheet. Moon counts for the giant planets keep changing, so they are written as "more than ...". Recheck them now and then.
- The periodic table data has one line per element (number, symbol, name, family, group, period). Elements 109–118 are "unknown properties". The study guide shows "How the table works" in the table's empty top area until an element is tapped.
- Both modules' content was fact-checked by a separate pass.

## 8e. Black Beauty notes
- Organized by Beauty's homes and the book's four parts (Part 1 ch. 1–21, Part 2 ch. 22–31, Part 3 ch. 32–45, Part 4 ch. 46–49), not chapter numbers, so it works with any edition.
- Content was fact-checked against the novel by a separate pass. Where the book is uncertain (Ginger's death), the text says "believes".

## 9. Parts of Speech notes
- Content is in `data.js`: the 8 `PARTS`, `SORT_WORDS` (words that nearly always do one job), `SENTENCES` (everyday), and `TRICKY` (words that switch jobs, for Label the sentence). Sentences are `word/tag` pairs.
- Grade-school conventions: articles (a, an, the) and number words count as adjectives; helping verbs are verbs. Content avoids possessives (my, his), this/that, and "to" + verb, because books disagree on how to label them.
- The content was reviewed by a separate pass for label accuracy. Re-review it whenever sentences are added.

## 10. Greek and Latin Roots notes
- Its own subject (`roots`, shown as "Greek and Latin Roots") with this module as the only entry. The module has no tags, so it never appears in another subject's Suggested area.
- Content is in `data.js`: `ROOTS` (18 roots: root, language, meaning, level, 2-3 words, a kid-friendly note, an example sentence, accepted typed answers, and the stems Explain it looks for), `TWO` (Insane words built from two roots), and `SORTS`. The list of roots and their meanings is the owner's. The words, notes, and two-root words were written for this module and fact-checked by a separate pass (ambi and amphi are cousins; the note says "remember amphi = both or around (Greek), ambi = both (Latin)").
- Levels: Easy = animal roots (7), Medium = bird roots plus malus, omnis, ex, eu (6), Hard = amphi, ambi, archos, kyklos, circum (5), Insane = words built from two roots. Quiz and Type the answer have a level picker. The Insane questions show the meaning of the second root, so the child has to recall what the listed root means.
- Mastery is per root and shared by Quiz and Type the answer. A root is mastered when at least 80% of its last 5 tries were right the first try (no hint, no second try) and it has had at least 3 tries. The module page shows "Roots mastered X of 18". The tool score sent to the hub is the number of roots mastered out of 18 (registry `masterAt: 18`). Saved in the module state: `roots` (last 20 tries per root), `missed`, `level`.
- A missed root is asked first in the next round (the quiz takes `keepOrder: true` so the module's order is kept), and small level pools repeat it within a round. Wrong choices never include a near-identical meaning (amphi, ambi, circum, and kyklos are never offered together).
- Study guide: all 18 roots by level with words and notes (and speaker buttons), the two-root words, and a Greek or Latin page. It gives no credit.
- Quiz and Type the answer have a "Skip, review later" button (`skip: true` in the shared tools): it shows the answer, gives no point, and records a miss, so the root is marked for review and comes back first in the next round.
- Flashcards are practice only. Sort it has three sets (animals, good/bad/around, Greek or Latin).

## 11. US States notes
- A Geography module (`modules/geography/us-states/`), no tags. Content is in `data.js`: `STATES` (50 records: name, capital, year admitted, order admitted with 1 = Delaware and 50 = Hawaii, motto, state bird, state flower, 3-4 notable cities that are not the capital, and optional `mottoNote` / `flowerNote` where a state has no adopted motto or a second official one) and `FLAGS` (50 simplified SVG drawings, one per state). The flags are drawn by hand: stripes, stars, and colors are exact where possible, and the detailed state seals are simplified, so they are recognizable but not exact.
- Facts were checked by a separate pass against Wikipedia's lists of state mottos and flowers and official sites. Georgia's motto is on its state seal but not officially adopted; Washington's is also seal-only; North Dakota and South Carolina have a second official motto (shown as a note). Tennessee's iris is the state cultivated flower.
- Tools: Study guide (six sections with a find box) and Flashcards are practice only. Quiz (Mixed, Capitals, Flags, Mottos, Birds, Flowers, Cities, Admitted) and Type the answer (Capitals, Name the state, Flags, Birds, Flowers, Years, Order) both have a topic picker (saved in `state.topic`) and a Skip button; Put in order has three sets (all 50, the first 13, the last 10) and uses 6 states per round. Mastery is the registry default (best round of 8 of 10, or 80% in place for order).
- Questions never ask "which state has this bird or flower" because many states share them. A "which state?" city question is only asked for a city name that appears once in the data. Wrong choices never repeat the right answer.
- `quiz` takes an optional `html` field per question (extra markup such as a flag). The test hook `window.__usTest` exposes the question builders so `us_states_test.py` can check every state.
